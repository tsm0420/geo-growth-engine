## Present usefulness

A developer or product owner can initialize configuration, install five skills, audit a local export, inspect supplied store text, connect questions to sourced facts, import recorded answers, and compare retained reports. This is a usable evidence-preserving review toolkit; the user still supplies exports, facts, questions and answer records. Current main contains capabilities newer than the published alpha 1. [Setup and command contract][setup]

Action guidance already exists: each finding has `action`, rendered under **Next action**; there is no `nextAction` property. Audits provide concrete repairs and explicit unknowns. Planning sorts declared priorities and retains unsupported questions as research gaps; source URLs are traceability pointers, not independently verified facts. A new generic “next actions” field or content opportunity list would overlap existing behavior. [Report renderer][report], [content planner][plan]

Visibility already includes exact question/provider/surface/model/locale `queryGroups`, raw JSONL and a digest. The retained fictional package report demonstrates mixed errors, null rates and numeric zero. Default comparison compares finding IDs/status/evidence/action; optional `--visibility-metrics` compares six headline totals. Both preserve complete parsed source reports and digests. Neither aligns question cohorts, authenticates collection or establishes improvement. Query breakdown or aggregate arithmetic should not be proposed as missing. ## Recommended next slices

These are proposed planning priorities, not authorization to resume development. Favor one website/SaaS owner workflow because the retained real case covers that surface; this is an evidence-based focus choice, not demonstrated market preference.

1. **Validate independent first use before adding features.** Observed burden: a separate Node 24 toolkit checkout/build, three edited YAML files, a local export and fresh report directories. Consolidate current-main guidance into a version-pinned first-product runbook and candidate; reuse existing installation and rehearsal. Exclude a release, dashboard, global install and automated production repair. Evidence gate: one consented participant completes setup, chooses a finding and retains before/after reports; record actual blockers and distinguish developer execution from participant execution. Whether onboarding prevents adoption remains a hypothesis. [Setup][setup]

2. **Specify repeatable manual visibility collection and a small pilot.** Observed gap: provenance and collection comparability explicitly remain unknown; reports cannot establish whether two batches answer the same product/question conditions. Reuse existing JSONL, raw evidence, query groups and comparison; propose a collection worksheet/manifest identifying conditions, repeat attempts, errors and receipt locations, plus one owner decision record linking evidence to a chosen action. Exclude paid sampling, consumer scraping, automatic provenance certification, significance claims and publishing. Evidence gate: obtain consented genuine answer records and receipts for two disclosed batches, preserve originals, record one actual owner decision, and review changed/missing conditions before selecting automation. No genuine visibility outcome is verified by this assessment. [Visibility][visibility], [configuration contract][conditions]

Defer executable exact-query/context repeat comparison and cross-report action prioritization. Query rows already exist and headline differences already work; no independent user evidence establishes that manual review is the next bottleneck. The pilot should name a repeated decision that existing outputs cannot support before a third implementation issue is accepted. Any future alignment must keep missing/error-only rows and changed conditions explicit; matching labels alone cannot certify comparable cohorts. [Visibility][visibility], [compare][compare]

No independent adoption, retention, willingness-to-pay or product growth evidence was established. Keep ASO breadth, live crawling and hosted services deferred until a selected workflow supplies a concrete need.
