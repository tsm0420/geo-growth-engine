## Problem and solution

The maintainer wants useful development to continue after the finite hardening queue, with quiet marketplace tracking. Replace the deleted native goal with docs/iterative-goal.md and reuse the existing same-chat six-hour heartbeat geo-agensi. Keep development progress in the existing ledger and marketplace observations in dated receipts.

## User stories

1. As a maintainer, I receive review outcomes and required actions without repeated pending notices.
2. As a toolkit user, I receive small verified improvements selected for evidence integrity, first use or useful reports.
3. As a reviewer, I can distinguish proposed directions, shipped behavior, historical receipts and fresh verification.

## Decisions

The goal owns priorities and boundaries. Keep at most three accepted next slices; each feature needs a narrow contract before implementation. The Agensi baseline is five Free / Pending Review, zero Live; unknown access does not block unrelated development. Reuse the existing automation identity and notification setting. REA is appropriate for distributed artifact/runtime evidence, not ordinary source analysis.

## Verification seams

This setup changes documentation and app configuration, with no executable source. Check native goal creation through its returned objective/status and compare the objective's hash with the saved file after surrounding-whitespace normalization (the native tool trims it). Verify saved heartbeat status, six-hour interval, target thread and file pointer after tool updates. Validate submission receipt hashes against raw retained DOM evidence. Pin changed-document hashes for separate Standards and Spec reviews; check local links and whitespace. Unchanged product source/ZIPs do not justify claiming new product test runs. Future source slices use the existing real CLI acceptance seam and required tests/build/package/CI gates.

## Out of scope

Paid services, new external runtime providers, private-data publication, production changes, automatic merges/releases, payout onboarding, unsupported live-listing claims and bypassed terms/access approval.

## Completion

The setup slice completes when the replacement native goal matches its file, the existing heartbeat reads that goal, submission status is accurate, independent document reviews have no unresolved findings and delivery is reviewable. This is a milestone within ongoing development, not completion of marketplace review or the continuing goal.
